# 📸 食味値判定結果 写真撮影・OCR読み取り 仕様書

本仕様書は、「らくらく営農日誌 Next」の **収穫・刈取モード** における **食味計画面および米穀検査伝票の写真撮影・OCR読み取り機能** の読み取り項目定義と、OCR / Vision API 連携方式の選定・設計を定めたものです。

---

## 1. 対象帳票・機器の分類と実物サンプルに基づく読み取り項目定義

現場で発生する食味・品質データは、大きく以下の2種類の媒体から取得されます。

1. **食味計・穀粒判別器の画面（液晶・感熱紙レシート）**
   - 例：サタケ（食味計 STA1A / 穀粒判別器 RGQI）、静岡製機（食味分析計 TMシリーズ）、ケツト科学研究所（AN-820 等）、乾燥機付帯食味計
2. **JA・米穀検査機関の検査伝票（等級検査結果通知書・食味分析結果表）**
   - 例：JA荷受伝票、農産物検査結果通知書、ライスセンター乾燥調製・食味分析票

### 1.1 読み取り項目スキーマ（JSON構造定義）

| 項目キー (`key`) | 表示名 | 型 | 単位 | 想定レンジ / 値 | 抽出対象（食味計 / 検査伝票） | 優先度 |
| :--- | :--- | :---: | :---: | :--- | :--- | :---: |
| `tasteScore` | **食味値** | `number \| null` | 点 | `40` 〜 `100`（通常 65〜92） | 食味計 / 分析結果表 | **必須** |
| `moisture` | **玄米水分量** | `number \| null` | `%` | `10.0` 〜 `25.0`（通常 14.0〜16.0） | 食味計 / 検査伝票 | **必須** |
| `protein` | **タンパク含有率** | `number \| null` | `%` | `4.0` 〜 `12.0`（通常 5.5〜8.5） | 食味計 / 分析結果表 | **必須** |
| `amylose` | **アミロース含有率** | `number \| null` | `%` | `5.0` 〜 `30.0`（通常 15.0〜22.0） | 食味計（対応機種） | 任意 |
| `wholeGrainRate` | **整粒歩合（整粒率）** | `number \| null` | `%` | `30.0` 〜 `100.0`（通常 65.0〜95.0） | 穀粒判別器 / 検査伝票 | 推奨 |
| `fattyAcid` | **脂肪酸度** | `number \| null` | `mgKOH/100g` | `5.0` 〜 `50.0` | 食味計（一部機種） | 任意 |
| `grade` | **検査等級** | `string \| null` | - | `"1等"` / `"2等"` / `"3等"` / `"規格外"` | 検査伝票 | **必須** |
| `harvestBags` | **荷受袋数（30kg換算）** | `number \| null` | 袋 | `1` 〜 `9999` | 検査伝票 | 任意 |
| `lotNo` | **伝票番号・ロットNo** | `string` | - | 例：`2026-KA-0142` | 検査伝票 | 任意 |
| `variety` | **品種名** | `string` | - | 例：`コシヒカリ` | 検査伝票 | 任意 |

### 1.2 表記ゆれ・正規化ルール
- **食味値**：`食味値` / `食味` / `味度` / `SCORE` / `総合評価` → 数値抽出（小数四捨五入または小数第1位まで）
- **水分**：`水分` / `水分率` / `M` / `MOIST` → `%` 除去して小数第1位
- **タンパク**：`タンパク` / `蛋白質` / `タンパク質` / `粗蛋白` / `PROTEIN` / `P` → 小数第1位
- **アミロース**：`アミロース` / `AMYLOSE` / `A` → 小数第1位
- **整粒歩合**：`整粒` / `整粒歩合` / `整粒率` → 小数第1位
- **検査等級**：`1等` / `１等` / `一等` → `"1等"`（2等・3等も同様）、`規格外` / `等外` → `"規格外"`

## 2. OCR / Vision API 連携方式の選定

オフライン対応PWA（サーバーレス構成）という本アプリの特性と、現場での撮影環境（液晶画面の反射・7セグ数字・手書きやドット印字の検査伝票）を踏まえ、以下の **ハイブリッド3層方式** を選定・実装する。

### 2.1 方式比較と選定結果

| 方式 | 精度（液晶・伝票） | オフライン動作 | コスト | 選定位置づけ |
| :--- | :---: | :---: | :---: | :--- |
| **① Gemini Vision API (`gemini-2.5-flash`)** | **◎ 非常に高い**<br>（項目名と数値の意味理解＋JSON直接出力が可能） | △（オンライン時） | 低（無料枠 / 従量課金極小） | **第1推奨方式（オンライン標準）** |
| **② Google Cloud Vision OCR + 正規表現** | ○（文字起こしは高精度だが項目紐付けのルール調整が必要） | × | 中 | 将来のGASプロキシ拡張候補 |
| **③ ローカル正規表現パーサー ＋ 手動補正UI** | △（テキスト入力・貼付からの自動抽出） | **◎ 完全オフライン** | 無料 | **オフライン / APIキー未設定時のフォールバック** |
| **④ 実物サンプル検証モード** | ◎（テスト用固定サンプル＋模擬画像生成） | **◎ 完全オフライン** | 無料 | **導入前デモ・動作確認用** |

### 2.2 採用アーキテクチャ・データフロー

```text
[スマホカメラ撮影 / 画像選択]
        │
        ▼ クライアント側前処理（Canvasリサイズ: 長辺最大1280px, JPEG品質0.82）
        │
        ├── オンライン ＆ Gemini APIキー設定済 ──▶ Gemini Vision API (responseMimeType: application/json)
        │                                              └─▶ 構造化JSON (tasteScore, moisture, protein, ...)
        │
        └── オフライン / APIキー未設定 ──────────▶ OCRテキスト貼付・ローカル正規表現パーサー ＋ 手動入力
        │
        ▼
[読み取り結果 確認・手動補正モーダル]
  - 各数値の最終確認・微調整
  - 「✅ 収穫フォームへ反映」ボタン
        │
        ▼
[収穫・刈取フォーム ＆ 作業ログ (`workLogs`) へ保存]
  - 圃場カルテ・タイムライン・JA帳票に即時反映
```

### 2.3 セキュリティ・プライバシー設計
- **APIキーの保護**：Gemini APIキーはブラウザの `localStorage`（独立キー `rakuraku_einou_taste_ocr_cfg_v1`）にのみ保存し、**JSONバックアップファイルには含めない**。
- **画像データの扱い**：撮影画像はブラウザメモリ上でリサイズ圧縮してAPI送信するのみで、`localStorage`（容量上限5MB程度）を圧迫しないようログには数値・テキストメタ情報のみを永続化する。
